# Менеджер проєктів і задач

Настільний застосунок з графічним інтерфейсом для обліку проєктів, учасників і задач.
Курсова робота з дисципліни «Об’єктно-орієнтоване програмування»
(ВСП «Одеський технічний фаховий коледж ОНТУ», група 3РП-11, Долинський О. Д.).

## Можливості

- Створення, редагування й видалення проєктів, учасників і задач з перевіркою введення
  (дедлайн у межах проєкту, оцінка годин додатна, унікальна назва, коректна дата).
- Пошук задач за назвою, фільтрація за статусом, пріоритетом і виконавцем,
  сортування за дедлайном, назвою, пріоритетом і статусом.
- Три типи робочих елементів: задача (`Task`), помилка (`Bug`), віха (`Milestone`);
  прогрес кожного рахується за власним правилом, прогрес проєкту – середнє значення.
- Імпорт та експорт даних у JSON, експорт XML-звіту про прострочені задачі за проєктами.
- Фонові операції з індикатором виконання: імпорт великого файлу, розрахунок
  навантаження учасників, пошук прострочених задач (частинами в `ThreadPoolExecutor`).
- Обробка помилок (пошкоджений або неповний JSON, неіснуючий виконавець, некоректна дата)
  і журнал подій у файлі `tasks.log`.

## Вимоги

- Python 3.14.
- Лише стандартна бібліотека (`tkinter`, `json`, `xml.etree.ElementTree`, `threading`,
  `queue`, `concurrent.futures`, `logging`, `abc`). Додаткові пакети встановлювати не потрібно.
- Tkinter входить до стандартної поставки Python для Windows.

## Запуск

З кореня проєкту:

```
python main.py
```

Під час запуску автоматично завантажується файл `data/projects.json`
(у фоновому потоці). Параметри:

```
python main.py --file data/projects_large.json   # інший файл для стартового завантаження
python main.py --empty                           # почати з порожніх даних
```

Якщо вказаного файлу немає, застосунок запускається з порожніми даними.

### Швидка підказка щодо інтерфейсу

- Зліва: список проєктів і список учасників. Справа: пошук і фільтри та таблиця задач
  вибраного проєкту.
- Подвійне клацання по рядку відкриває редагування, клавіша `Delete` у таблиці задач
  видаляє вибрану задачу (з підтвердженням).
- Клацання по заголовку колонки змінює сортування (повторне клацання – зворотний порядок).
- Меню «Файл»: імпорт JSON, експорт JSON, XML-звіт про прострочені задачі, вихід.
  Меню «Операції»: навантаження учасників, прострочені задачі.
- Дати вводяться у форматі `YYYY-MM-DD`.
- Під час фонової операції кнопки редагування й пункти меню заблоковані.

```
python -m unittest discover -s tests -t . -v
```

Тести виконуються з кореня проєкту. Тести вікна автоматично пропускаються,

## Тестові дані та вимірювання

Усі команди виконуються з кореня проєкту.

Генерація даних (фіксоване зерно, результат відтворюється):

```
python -m tools.generate_data --projects 5 --items 12 --members 6 --output data/projects.json
python -m tools.generate_data --projects 100 --items 120 --members 20 --output data/projects_large.json
python -m tools.generate_data --projects 1 --items 10000 --members 20 --output data/projects_single.json
python -m tools.generate_data --projects 100 --items 100 --members 20 --output data/projects_100x100.json
```

Набір пошкоджених файлів для ручної перевірки імпорту (19 сценаріїв):

```
python -m tools.make_broken_files
```

Файли записуються в `data/broken`; кожен має викликати повідомлення про помилку,
а наявні дані в застосунку мають лишатися без змін.

Порівняння одно- та багатопотокового режимів (S = T1/Tn, E = S/n):

```
python -m tools.benchmark --file data/projects_large.json --repeats 20 --output data/benchmark.md
```

Порівняння часу завантаження файлів:

```
python -m tools.benchmark_load --files data/projects_single.json data/projects_100x100.json data/projects_large.json --repeats 3 --output data/benchmark_load.md
```

## Формат даних

### JSON (`data/projects.json`)

```json
{
  "members": [
    {"id": 1, "name": "Олена Коваль", "role": "Developer"}
  ],
  "projects": [
    {
      "id": 1,
      "name": "Проєкт 1",
      "start": "2026-01-01",
      "end": "2026-12-31",
      "items": [
        {
          "type": "Task",
          "id": 1,
          "title": "Підготувати макет",
          "assignee_id": 1,
          "priority": "high",
          "status": "in_progress",
          "deadline": "2026-06-30",
          "estimate_hours": 8
        }
      ]
    }
  ]
}
```

- `type`: `Task`, `Bug` або `Milestone`.
- `priority`: `low`, `medium`, `high`.
- `status`: `todo`, `in_progress`, `done` (малими літерами).
- `assignee_id` посилається на `id` учасника зі списку `members`.
- Ідентифікатори учасників, проєктів і задач унікальні; назви проєктів унікальні
  без урахування регістру; дедлайн лежить у межах дат проєкту.
- Файл, який не відповідає цим правилам, відхиляється повністю, наявні дані не змінюються.

### XML-звіт

```xml
<report date="2026-07-01">
  <project id="1" name="Проєкт 1" overdue_count="1">
    <item id="3" type="Task">
      <title>…</title>
      <assignee>…</assignee>
      <deadline>2026-06-01</deadline>
      <status>todo</status>
      <priority>high</priority>
      <days_overdue>30</days_overdue>
    </item>
  </project>
</report>
```

Проєкти без прострочених задач потрапляють у звіт з `overdue_count="0"`.
Задача прострочена, якщо дедлайн раніший за дату звіту й статус не `done`.

## Архітектура

Шаблон MVP, шари розділені так, що презентер не імпортує `tkinter`.

```
project_manager/
  main.py                  точка входу, налаштування журналу, збирання застосунку
  models/                  Trackable, WorkItem, Task, Bug, Milestone, Member, Project, enums
  repository/              JSONRepository (імпорт/експорт), XmlReportWriter
  services/                ProjectService (CRUD, пошук, фільтри, сортування, файли),
                           BackgroundTasks (пул потоків, черга повідомлень)
  presenters/              MainPresenter, протокол MainView
  views/                   MainWindow, діалоги, підписи інтерфейсу
  tools/                   генератор даних, пошкоджені файли, вимірювання
  tests/                   unittest
  data/                    приклади даних
  DESIGN.md                специфікація і ухвалені рішення
  AI_LOG.md                журнал використання інструментів ШІ
```

Основні рішення:

- `WorkItem(Trackable)` абстрактний; `Task`, `Bug`, `Milestone` перевизначають `progress()`.
  `Project` агрегує задачі й перевіряє правила рівня проєкту; редагування задач іде через
  `Project.update_item()`.
- Усі зміни даних проходять через `ProjectService`; спільні списки захищено `RLock`.
- Фонові потоки не звертаються до віджетів: вони пишуть повідомлення в `queue.Queue`,
  а вікно опитує чергу через `after()` і оновлює інтерфейс.
- Помилки валідації – `ValueError`, помилки файлів – `DataFormatError`;
  презентер перетворює їх на повідомлення користувачу.
